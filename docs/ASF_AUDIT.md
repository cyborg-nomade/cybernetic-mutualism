# Running the Offline ASF Audit

This tool implements the [registered ASF comparison](../research/cases/asf-autonomy-coordination-preregistration.md).
Start with the [implementation record and proposed clarification](../research/cases/asf-autonomy-coordination-tooling.md).
The tool has no retrieval command. The current item stops at review and freeze
before any case evidence is collected.

## Quick Start Without Evidence

From the repository root:

```bash
uv sync --locked
uv run --locked python -m scripts.asf_audit --help
uv run --locked python -m scripts.asf_audit init /tmp/asf-blank
uv run --locked python -m scripts.asf_audit sample /tmp/asf-blank
uv run --locked python -m scripts.asf_audit validate /tmp/asf-blank
uv run --locked pytest tests/test_asf_calculators.py tests/test_asf_audit_workflow.py
```

`init` creates a new directory containing header-only CSV files and
`schema.json`; it refuses to overwrite an existing directory. A blank dataset
has no evidence and deliberately fails integrity validation. `sample` reports
all 48 baseline strata, including empty strata, and the audit family union.
No empirical or claim result is generated by these commands.

## Ledger Reference

Every CSV has an exact header, UTF-8 encoding, and string-valued cells. Follow
the generated enumerations and the codebook. Separate multiple original IDs
with semicolons. Use neutral stable identifiers without pipes, except the
documented episode identity `project|earliest_original_source_id`. Do not put
causal labels in identifiers or original-source locators. Blanks mean unfinished
entry; `unknown` is an explicit coded value, never a numerical zero.

| Table | Purpose |
| --- | --- |
| `sources.csv` | One original source per ID: canonical URL, locator, event interval, publication/retrieval dates, content hash, authority citation, access state, publication eligibility, and original registration SHA. Store exact local bytes under `sources/`; do not publish bulk correspondence. |
| `cohort.csv` | Dated opening eligibility of the four fixed projects, with source references. |
| `coverage.csv` | Development-index and included-thread availability for each project/month; board minutes or official no-meeting declarations in rows with project `foundation`. Record unknowns and failures explicitly. |
| `special_meetings.csv` | Separately inventoried announced special meetings and their records. An empty table needs an evidenced complete-calendar attestation. |
| `screening.csv` | Every subject-index entry, its original ID/date, inclusion/exclusion reason, underlying family, and candidate type. Preserve all local-release openings, including unsampled ones. |
| `families.csv` | Underlying independent requested deliverable, project, initiating role, action class, onset interval, earliest original source ID, known exposure, de-duplication rationale, and the complete source bundle. A shared directive retains one family ID across PMCs. |
| `episodes.csv` | Episode identity from project and earliest original source ID; requested change, actors, original option, disposition history, and independent viability reason/duration. Use explicit unknowns where unobserved. |
| `measurements.csv` | Complete fixed grid of two directions × three horizons per coded family/project. Keep measurement fields separate from opportunity and four causal-condition fields. Identify distinct underlying acts, their source IDs and intervals, principal episode, and authority before/after. |
| `evidence.csv` | One locator per record/field/source support relation. Positive fields require a usable source and nonempty locator. Evidence sufficiency is a researcher judgment. |
| `shocks.csv` | Independently evidenced shocks, onset, project exposure differences, external precursor status, and explicit continuation records. |
| `shock_searches.csv` | Per opportunity/horizon search from 30 days before earliest initiation through the horizon after latest initiation; both project and foundation frames, including explicit negative searches. |
| `rivals.csv` | Five registered rival/focal accounts per opportunity: state, supporting/contrary/missing information, source IDs, and explanation. Only contradiction addresses either sufficient family-level alternative. |
| `contrasts.csv` | Deterministic comparison family, or explicit absence, plus source-linked within-episode contrast when available. |
| `attestations.csv` | Named completeness assertions, source IDs, and rationale. Required names are listed below; software cannot independently establish these facts. |

Required completeness assertions are `complete_subject_indices_screened`,
`board_and_officer_reports_screened`, `special_meeting_calendar_complete`,
`shock_ledger_precedes_witness_labels`, `family_deduplication_reviewed`, and
`all_required_records_coded`. State `yes` only when actually completed, with
notes explaining the check and source references when applicable.

Record event dates separately from publication and retrieval. Date intervals
use ISO dates, or offset timestamps normalized to UTC dates. A wholly unknown
interval uses `unknown` in both cells. Retrieval and lifecycle timestamps must
include an offset. Unknown publication time is explicit. For a known day-120
response with no evidence about earlier conduct, retain unknown disposition at
60/90 days; never forward-fill or invent an earlier zero.

`receiver_unchanged = yes` means affirmative evidence of the relevant receiving
option or commitment remaining unchanged at that horizon. It requires
`receiver_observed = known`, `effect_sign = no_demonstrated_effect`, and an
evidence locator. Neither unchanged coordination burden nor public silence is
enough. This explicit code implements the decision table's informative unchanged
outcome; it adds no field to the registered 18-field agreement denominator.

The `family.source_ids` bundle must include the complete relevant public source
material for recoding, including authority, contrasts, shocks, and negative
records. It must not consist only of sources selected to support a witness.
Source hashes check exact bytes; content interpretation and completeness remain
human work. Keep unnecessary personal data and copyrighted bulk material out of
public repository commits. Local snapshots can retain the audit bytes.

Current archive indices may establish availability even when their publication
date is unknown; they cannot supply decisive historical outcome evidence. Cohort
eligibility, minutes, and every causal/nested field still require eligible dated
sources under the publication cutoff. The distinction concerns retrieval
metadata, not an extension of the historical observation window.

## Workflow After Separate Evidence Authorization

1. Inventory sources and dated authority; fill the access tables and use
   `access DATASET` to calculate G1. Publish the map and stop the registered
   comparison if it fails. Missing minutes or project eligibility cannot be
   repaired by replacing projects.
2. Screen the required entire frame. Use `sample DATASET` to preserve the local
   baseline log. Include every cross-boundary candidate and eligibility-resolving
   thread. Complete measurements before witness classifications and the shock
   ledger before causal labels. Recompute comparison selection mechanically.
3. Complete the disclosed audit-only supplement selected from the full eligible
   universe. Keep those routine releases out of primary analysis. Resolve any
   discovered cross-boundary opportunities into the census before lock.
4. Run `validate DATASET`. Resolve entry errors against sources, preserving
   substantive unknowns. A check cannot assess the meaning of a source.
5. Lock the completed first pass and generate the frame and blank recode bundle
   at the same point. Record the returned digests externally before washout.
   The lock command produces no aggregate result or claim decision.

```bash
uv run --locked python -m scripts.asf_audit lock DATASET --output LOCK_DIRECTORY
```

`LOCK_DIRECTORY` must be new and outside `DATASET`. It contains `first-pass/`,
`audit-frame.json`, `blank-recode/`, and `lock.json`. The manifest records hashes
of source bytes, every input ledger, protocol files, Python code, and `uv.lock`.
Retain its `lock_sha256` in the evidence item's commit or review record. Hashes
detect changes against that retained value; they are not a trusted timestamp
service and cannot prevent deliberate replacement of all records.

6. Wait until the returned `recode_not_before` timestamp without opening the
   locked tables, inspecting the bundle early, or doing other ASF evidence
   work. No script can verify abstention or erase source memory.
7. At actual recode start, record the abstention attestation:

```bash
uv run --locked python -m scripts.asf_audit start-recode LOCK_DIRECTORY \
  --lock-hash LOCK_SHA256 --no-asf-evidence-work
```

Copy `blank-recode/recode.csv` to a working file outside the frozen bundle.
Use only the public source material in the bundle to recode every blank field,
keeping neutral IDs and the fixed grid. The two direction slots are questions
asked of every family, not earlier opportunity labels. Do not consult the first
pass or ask an AI to impersonate an independent coder. The original bundle must
remain unchanged so its hash can be verified.

8. Submit once, before reconciliation:

```bash
uv run --locked python -m scripts.asf_audit submit-recode LOCK_DIRECTORY \
  --lock-hash LOCK_SHA256 --recode COMPLETED_RECODE.csv
```

This exclusively creates `submitted-recode.csv`, records initial agreement in
`initial-score.json`, and generates `reconciliation.csv`. Retain the returned
`score_sha256` externally. A failed or interrupted attempt must be disclosed;
do not delete its submission marker and rerun until it passes. Missing fields
are scored disagreements, including absent rows. Invalid values and injected
IDs fail integrity. Per-field unknown rates and known-value agreement accompany
the initial aggregate.

9. Inspect each disagreement in `reconciliation.csv`. Preserve `first_value`
   and `recode_value`. Set `status` to `resolved` with final value, original
   source IDs, locator, and rationale, or `unresolved` with rationale. Unresolved
   witness/date disputes remove the witness; unresolved authority/nested-outcome
   disputes remove nested support. Initial agreement is never recalculated from
   reconciled values. New evidence or a software correction requires a dated
   amendment, not an unnoticed edit to frozen files.

   A resolution can require a dependent correction to a field on which both
   passes agreed (for example, a corrected date invalidates a witness flag).
   Add a separate adjudication row for that field, preserving its actual values
   in both passes and citing the frozen evidence and reason. These corrections
   do not alter the initial agreement or resample the audit frame. A final row
   whose dates, conditions, and witness flag disagree fails integrity.
10. Calculate the report:

```bash
uv run --locked python -m scripts.asf_audit adjudicate LOCK_DIRECTORY \
  --lock-hash LOCK_SHA256 --score-hash SCORE_SHA256 > report.json
```

The report verifies provenance and initial arithmetic, retains failures, and
reports the 90-day primary category, both sensitivity categories, per-direction
denominators and signs, nested results, blocked conditions, and conditional
claim decisions. Descriptive response counts are explicitly project-response
counts, not independent-family counts. G3 fails for initial agreement below
90% or any integrity error. Failed gates cannot upgrade confidence.

An access failure needs no invented first pass or recode. A wholly empty
eligible frame cannot provide a stability percentage: report the access or
identifiability stop and the empty screening inventory as such. More generally,
unfinished collection is incomplete work, not a passed or negative experiment.

## Verification and Limits

`just check` runs the repository quality gates. The synthetic tests are local
and deterministic; they never fetch an ASF document. `validate` exits 1 on
integrity failures and malformed command/input errors exit 2. Scientific gate
failure in an otherwise valid report is reported in JSON, not treated as a
software crash. The Python calculation functions also support synthetic
calibration; use the staged CLI for a registered empirical run.

Source availability, substantive qualification, family independence, completeness,
and the washout declaration still require honest, documented interpretation.
The scripts are reproducibility checks, not independent reliability evidence.
Freeze the reviewed code before retrieval; later changes follow the dated
amendment procedure and cannot silently overwrite the earlier result.
